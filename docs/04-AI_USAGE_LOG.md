## 1. Prompt discipline (reusable template)

```
INTENT:        what outcome, in one sentence
CONTEXT:       relevant files/classes, framework versions, existing conventions
CONSTRAINTS:   must / must-not (e.g. no class-level @Transactional, time via Clock, no new dependencies)
ACCEPTANCE:    observable criteria / tests that must pass
OUTPUT FORMAT: files to create or change; no unrelated refactors
```

Iteration rule: if the output is wrong, change the *prompt's constraints or acceptance criteria*, not just "try again", and
record why the first attempt was rejected.

## 4. Secure AI usage rules applied
- No secrets, tokens or customer data were put into prompts; the only credential-like value is a placeholder salt.
- Dependencies come from the Spring Boot BOM plus Flyway (BOM-managed) and build-time tooling only: JaCoCo, Checkstyle, SpotBugs, OWASP dependency-check (all Maven plugins, pinned versions). No runtime third-party libraries beyond Boot's.
- Generated code is treated as untrusted until it passes tests and your review.
- AI was never given authority to deploy, push or change settings; all outputs are files you review.

## 5. High-impact changes requiring explicit human sign-off
| Change | Why it is high-impact | Reviewer checklist |
|---|---|---|
| SSRF guard (`UrlValidator`) | Security boundary | Are all non-public ranges covered? Is rejecting unresolvable hosts acceptable? DNS-rebinding limitation understood? |
| Rate limiting & client identity | Abuse control; spoofing | Is `trust-forwarded-for=false` right for your deployment? Fail-open acceptable? Limiting every state-changing method (not just `/api`) intended? |
| Targeted UPDATEs (`deactivateByCode`, `updateExpiry`) and `PATCH` semantics | Data integrity; who may change what | Do you accept "expired links can be revived, deactivated cannot" (ADR-010)? No auth: any caller can change any link |
| Quality-gate configuration (Checkstyle/SpotBugs/OWASP) | Silent suppression risk | Are the SpotBugs exclusions in `config/quality/spotbugs-exclude.xml` genuinely false positives? |
| Schema / Flyway migration `V1` | Data safety | Does the SQL match the entities exactly (types, constraints, index names)? Run `FlywayMigrationIntegrationTest` and diff against Hibernate's generated DDL once |
| Analytics privacy design | Compliance | Salt managed as a secret? Retention policy for `click_events`? |
| Redirect status & caching | Product behaviour | 302/`no-store` vs performance at scale |
