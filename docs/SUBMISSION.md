## 4. How to present it (talking points)

1. **Framing:** "AI accelerated drafting within specified tasks; I own correctness." Show one task card (`03-SCENARIOS.md`) and the matching log row.
2. **Strongest engineering story:** uniqueness via DB constraint, not check-then-insert (ADR-002) – with the race tests.
3. **Honest trade-offs:** best-effort analytics (ADR-004), fail-open limiter, DNS-rebinding caveat, no auth.
4. **Why no orchestrator:** brief says engineer-led, not autonomous; both reference repos built one (ADR-006); the brief's wording is the justification – be ready for "why not?".
5. **What you'd do next:** Postgres + Flyway, cache with invalidation, write-behind queue, auth/ownership, retention/rollups.

Likely follow-ups: *Why 302?* (ADR-003) · *What if two clients send the same alias?* (ADR-002) · *What if analytics is down?* (ADR-004, counter) · *Is the SSRF guard sufficient?* (no – DNS rebinding; re-validate on any server-side fetch) · *Why is `X-Forwarded-For` ignored?* (spoofable; opt-in).
